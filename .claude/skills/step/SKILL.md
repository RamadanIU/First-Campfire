# Выполнение шага дорожной карты

Аргумент (необязателен): номер шага, например `1.4`. Без аргумента — первый невыполненный шаг.

Полный регламент — в `docs/PROCESS.md`. Прочитай его целиком перед началом: он обязателен.
Ниже — контрольный список, чтобы ничего не пропустить.

## 1. Начало

- [ ] `npm run next` — узнать шаг (или взять номер из аргумента).
- [ ] Проверить открытые PR: если PR предыдущего шага не слит — остановиться и сообщить владельцу.
- [ ] `npm run check` на исходном состоянии — зелёный.
- [ ] Прочитать: `docs/STATUS.md`, карточку шага и вступление этапа в `docs/roadmap/stage-NN.md`,
      отчёты 1–2 предыдущих шагов в `docs/journal/`, разделы GDD из карточки, `docs/ARCHITECTURE.md`.
- [ ] Если карточка шага краткая (этапы 6–12) — сначала детализировать её.
- [ ] Составить план и коротко сообщить его владельцу.

## 2. Работа

- [ ] Реализовать шаг небольшими коммитами (`шаг <id>: …`), с тестами.
- [ ] Каждый критерий «Готово, когда» подтверждён тестом, выводом команды или скриншотом.
- [ ] Вне рамок шага ничего не делать; находки — в `docs/BACKLOG.md`.

## 3. Проверка

- [ ] `npm run check` зелёный.
- [ ] `npm run shot -- --step <id> имя="?…" …` — 2–5 кадров; каждый открыт и оценён глазами.
- [ ] С шага 0.6: `npm run sim` на нескольких зёрнах, показатели — в отчёт.
- [ ] Контрольные сцены из `docs/STATUS.md` не сломаны.

## 4. Запись прогресса

- [ ] `docs/journal/<id>.md` по шаблону `docs/journal/TEMPLATE.md`.
- [ ] `docs/STATUS.md` переписан под новое состояние.
- [ ] `npm run roadmap -- done <id>`.
- [ ] При необходимости: `ARCHITECTURE.md`, `DECISIONS.md`, `ART.md`, `BACKLOG.md`, карточки будущих шагов.

## 5. PR и отчёт

- [ ] Commit, push в ветку сессии, PR в `main` по шаблону; заголовок `Шаг <id> — <название>`.
- [ ] Скриншоты в описании PR: `npm run roadmap -- shots <id>` (после push).
- [ ] CI зелёный.
- [ ] Итоговое сообщение владельцу по форме из `docs/PROCESS.md`, раздел 6, со скриншотами.

Один шаг за сессию. Следующий шаг не начинать.
