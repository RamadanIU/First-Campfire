# «Первый костёр» — правила работы в репозитории

Автономный 2D pixel-art симулятор эволюции цивилизации: двое людей у костра → город. Игрок только наблюдает.
Игра создаётся **по шагам дорожной карты: одна сессия — один шаг**. Каждая сессия начинается с нуля и
знает о проекте только то, что записано в репозитории. Поэтому главное правило:

> **Что не записано в репозитории — того не существует. Шаг не закончен, пока прогресс не отмечен, а PR не создан.**

Владелец проекта не программист. Он оценивает работу по скриншотам, отчёту и живой сборке.
Пиши ему по-русски, простыми словами, без жаргона.

## С чего начать сессию

1. `npm run next` — покажет следующий шаг и путь к его карточке (при старте сессии это уже выведено автоматически).
2. Прочитай по порядку:
   - [`docs/PROCESS.md`](docs/PROCESS.md) — **обязательный порядок работы** (начало, проверка, запись прогресса, PR, отчёт);
   - [`docs/STATUS.md`](docs/STATUS.md) — что игра умеет сейчас, известные проблемы, подсказки следующему шагу;
   - карточку своего шага в `docs/roadmap/stage-NN.md` и отчёт предыдущего шага в `docs/journal/`;
   - разделы GDD, указанные в карточке (`docs/gdd/`), — только их, весь GDD читать не нужно;
   - [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — устройство кода и правила, которые нельзя нарушать.
3. Если пользователь назвал конкретный шаг — делай его. Если написал «следующий шаг», `/step` или ничего конкретного — делай шаг из `npm run next`.

## Нерушимые правила

1. **Один шаг за сессию.** Не начинай следующий, даже если осталось время: лучше довести текущий до блеска.
2. **Игра всегда запускается.** После любого шага `npm run check` зелёный, игра открывается и работает.
3. **Проверяй глазами.** Сними скриншоты (`npm run shot`), открой их и оцени сам: если выглядит плохо или сломано — шаг не готов.
4. **Отметь прогресс:** отчёт `docs/journal/<id>.md`, обновлённый `docs/STATUS.md`, `npm run roadmap -- done <id>`.
5. **Всегда создавай PR** в `main` по шаблону, со скриншотами в описании, и дождись зелёного CI.
6. **Итоговое сообщение владельцу** — со скриншотами, по форме из `docs/PROCESS.md`.
7. **Не выходи за рамки шага.** Идеи и найденные проблемы вне шага — в `docs/BACKLOG.md`.
8. **GDD — источник истины о дизайне.** Не меняй файлы `docs/gdd/`. Расхождение с GDD допустимо только как
   записанное решение в `docs/DECISIONS.md` с объяснением.
9. **Не ослабляй проверки ради зелёного результата**: не удаляй и не пропускай тесты, не отключай правила линтера.

## Архитектура в пяти строках

- `src/sim/` — симуляция: детерминированная (одно зерно — одна история), без браузера, без `Math.random` и часов.
- `src/render/`, `src/ui/`, `src/app/` — отрисовка (Canvas 2D), интерфейс, запуск. Только читают состояние симуляции.
- `src/art/` — графика как код: спрайты описаны текстом и палитрой, картинок-файлов в репозитории нет.
- `data/*.json` — таблицы содержания и баланса (ресурсы, здания, технологии…). Содержание — в данных, не в коде.
- `tools/` — скрипты: дорожная карта, скриншоты, прогоны без графики.

Подробности и остальные правила — в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Команды

| Команда                                      | Что делает                                                                               |
| -------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `npm run next`                               | Следующий шаг дорожной карты                                                             |
| `npm run dev`                                | Игра в браузере с горячей перезагрузкой                                                  |
| `npm run check`                              | Всё сразу: линтер, типы, тесты, дорожная карта, сборка. **Должно быть зелёным перед PR** |
| `npm run format`                             | Автоисправление форматирования и простых замечаний линтера                               |
| `npm test`                                   | Тесты                                                                                    |
| `npm run shot -- --step <id> имя="?scene=…"` | Скриншоты в `docs/screenshots/<id>/` (заодно проверяет, что на странице нет ошибок)      |
| `npm run roadmap -- done <id>`               | Отметить шаг выполненным (проверит наличие отчёта и скриншотов)                          |
| `npm run roadmap -- shots <id>`              | Готовая разметка скриншотов для описания PR                                              |
| `npm run roadmap -- status`                  | Прогресс по этапам                                                                       |

## Соглашения

- Язык: документация, отчёты, PR, сообщения коммитов и тексты игры — **русский**; идентификаторы и комментарии в коде — английский.
- Коммиты: `шаг 1.4: сытость и жажда` (маленькие, по смыслу). PR: `Шаг 1.4 — Сытость и жажда`.
- TypeScript строгий, только «стираемый» синтаксис (без `enum`, `namespace`, параметров-свойств), импорты с расширением `.ts`.
- Новая зависимость в `package.json` — только с записью в `docs/DECISIONS.md` (по умолчанию обходимся без библиотек).
- Тесты лежат рядом с кодом: `foo.ts` → `foo.test.ts`. Сценарные тесты — в `tests/`.
