# Текущее состояние

> Снимок на конец шага **0.1**. Каждая сессия переписывает этот файл под новое состояние
> (это не история — история в `docs/journal/`).

## Что игра умеет

Пока ничего игрового: есть только **заставка** — ночная стоянка с костром, двое у огня, шалаш, название игры.
Она доказывает, что сборка, цикл отрисовки и скриншоты работают. Симуляции, мира и жителей ещё нет.

## Как это увидеть

| Что | Как |
|-----|-----|
| Живая сборка | <https://ramadaniu.github.io/First-Campfire/> (после включения GitHub Pages владельцем, см. `README.md`) |
| Локально | `npm run dev` |
| Заставка | `?scene=title` (сцена по умолчанию) |

Параметры адресной строки: `scene` (сцена), `seed` (зерно), `frame` (замороженный кадр анимации — для
одинаковых скриншотов), `ui=0` (скрыть интерфейс).

## Контрольные сцены

Кадры, которые каждая сессия проверяет на отсутствие регрессий:

| Сцена | Параметры | Что должно быть видно |
|-------|-----------|-----------------------|
| Заставка | `?scene=title&frame=12` | Ночь, костёр со свечением, двое у огня, шалаш, название, без ошибок на странице |

## Устройство (кратко)

- `src/main.ts` — запуск: читает параметры, выбирает сцену, крутит цикл кадров; сообщает о готовности через `window.__fc`.
- `src/app/params.ts` — разбор параметров адресной строки. `src/app/scenes.ts` — реестр сцен. `src/app/titleScene.ts` — заставка.
- `tools/roadmap.ts` — трекер дорожной карты. `tools/screenshot.ts` — скриншоты.
- `src/sim`, `src/data`, `src/render`, `src/art` — пока пустые; правила для них уже действуют (`docs/ARCHITECTURE.md`).

## Известные проблемы

- **GitHub Actions не запускается: аккаунт владельца заблокирован из-за проблемы с оплатой** (сообщение GitHub:
  «The job was not started because your account is locked due to a billing issue»). Пока владелец не исправит это
  в настройках оплаты GitHub, проверки в PR будут красными за 2–3 секунды, а публикация на GitHub Pages не работает.
  Это не ошибка кода; порядок действий — `docs/PROCESS.md`, раздел 5. Когда Actions заработает, первая же сессия
  должна убедиться, что `ci.yml` и `deploy.yml` действительно проходят (они ещё ни разу не выполнялись).
- Заставка нарисована прямоугольниками в коде — временно, до шага 0.4.
- Визуальных проверок в CI нет: скриншоты снимаются только в сессии.
