# Текущее состояние

> Снимок на конец шага **0.8** (ревизия этапа 0: фундамент перепроверен целиком). Каждая сессия переписывает этот
> файл под новое состояние (это не история — история в `docs/journal/`).

## Что игра умеет

- **Заставка** — ночная стоянка сверху, нарисованная спрайтами игры: двое у костра, шалаш, лес вокруг; ночь —
  синий фильтр, вокруг огня тёплый круг света ступенчатыми кольцами, искры, пламя мерцает. Внизу — **меню**
  (0.7): «Продолжить» (дата и зерно сохранённого мира), «Новый мир» (поле зерна, ↻ — случайное), «Загрузить из
  файла»; на телефоне меню стоит сразу под названием, над стоянкой.
- **Ядро симуляции** (0.2): мир шагает тиками; одно зерно — одна история. Календарь по GDD (сутки 400 тиков,
  сезон 3 дня, год 12 дней). Журнал событий с причинами. Игровой цикл: 10 тиков/с на ×1; скорости пауза / ×1 /
  ×2 / ×5 / ×20. Отладочная сцена `clock`; временная проверочная система — светлячки (единственная случайность
  в тике; остаются до ревизии 1.13 — ADR-017).
- **Графика как код** (0.3): спрайты — текстовые файлы `src/art/sprites/*.ts`, перекраска подменой рядов
  палитры, атлас, проверка спрайтов тестами. Формат и правила — `docs/ART.md`.
- **Лист стиля эпохи 0** (0.4):
  - **мастер-палитра** — 69 цветов мира + полупрозрачный цвет тени + 3 служебных (сцена `palette`);
  - **земля**: трава (3 вариации), земля, песок, мелкая и глубокая вода (рябь 4 кадра); **переходы** без контура
    и швов — высокая земля заходит на низкую неровным краем, у воды мокрый песок и пена;
  - **природа**: дуб, молодое дерево, берёза, пень, ягодный куст (с ягодами / пустой), камень, ветки, цветы,
    высокая трава; **стоянка**: костёр (горит 4 кадра / потух), шалаш, куча веток, лежанка;
  - **жители**: мужчина и женщина 12×18 — стоят (дышат) и идут в 4 стороны; 6 тонов кожи × 5 цветов волос;
  - **пузырьки**: еда, вода, сон, холод; **тени** под всем, что стоит;
  - **сцена `stylesheet`** — эталон стиля: стоянка у реки; женщина ходит к реке за водой.
- **Таблицы данных** (0.5) — содержание и числа в `data/*.json`, а не в коде:
  - `balance.json` — время, движение, жизнь (GDD §2.1, §13.1); **ядро берёт время отсюда**;
  - `resources.json` — все **33 ресурса эпохи 0** (GDD §5.2): категория, эпоха, стопка (еда — в рационах), срок
    порчи, значок; `terrain.json` — 5 типов земли: проходимость, скорость, вид;
  - загрузка с проверкой: ошибка называет файл, запись и поле и подсказывает опечатку; испорченная таблица —
    красное окно вместо игры, битая ссылка на значок — предупреждение поверх сцены;
  - **значки всех ресурсов** — спрайты вида `item` 10×10; **сцена `data`** показывает таблицы целиком.

- **Прогоны без графики** (0.6) — главный инструмент баланса: `npm run sim` проигрывает много миров в Node без
  экрана, по нескольку одновременно (потоки), с прогрессом в консоли:
  - **показатели мира** — список `src/sim/metrics.ts`, одна строка на показатель: счётчик, сумма, среднее,
    максимум, минимум по событиям журнала или число из состояния мира; итог за прогон и **срез за каждый год**;
  - **итог**: таблица в консоли (среднее, минимум, максимум по мирам и зерно мира с крайним значением),
    `worlds.csv` (строка на мир), `years.csv` (строка на мир и год), `summary.json` (сводка, кривые по годам, ошибки);
  - **время тика** в каждом прогоне — среднее, «99 % тиков не дольше», худший; скорость в игровых годах в секунду;
  - итог **воспроизводим**: те же параметры — те же байты (кроме столбцов времени) при любом числе потоков;
    «отпечаток прогона» — один хэш всех миров; мир, упавший с ошибкой, не роняет прогон (код выхода 1);
  - `npm run bench` — готовая настройка: 3 мира × 200 лет на одном потоке (точный замер скорости).

- **Сохранения** (0.7) — мир сохраняется и продолжается без изменения истории (5 000 тиков → сохранить →
  загрузить → ещё 5 000 = 10 000 подряд):
  - **формат** — одна строка JSON: заголовок (метка игры, версия формата, зерно, тик, контрольная сумма, отпечаток
    таблиц) и мир; типизированные массивы (для карты) уже поддержаны; `src/sim/save.ts`;
  - **плохое сохранение не роняет игру**: обрезанное, изменённое, чужой файл, из более новой или старой версии —
    понятное сообщение по-русски и предложение начать новый мир; изменились таблицы — только предупреждение;
  - **версия формата** поднимается при любом изменении устройства мира — следит тест «формы мира»;
  - **сцена `world`** — мир игрока: из автосохранения (localStorage), **автосохранение раз в игровой год и при
    закрытии вкладки** — перезагрузка возвращает в тот же мир на том же тике; панель «Мир»: когда сохранён,
    «Сохранить в файл», «В меню». Пока мир рисуется видом ядра (небо, светлячки, часы, журнал) — карта будет в 1.1;
  - переполнение или запрет хранилища — сообщение «сохраните мир в файл», игра идёт дальше;
  - **прогоны из сохранения**: `npm run sim -- --load файл --years N` — тот же мир, что в браузере, ещё N лет.
- **`npm run e2e`** (0.7) — сквозная проверка в настоящем браузере: меню, новый мир, перезагрузка, файлы, плохие
  сохранения, запрет и переполнение хранилища (26 проверок, ≈ 30 с; не входит в `npm run check`).
- **Проверка кадров по пикселям** (0.8) — опции `npm run shot`: `--check-crisp N` доказывает резкость пикселей на
  ×N (кадр с `ui=0`), `--compare папка` сравнивает кадры с прежними пиксель в пиксель
  (`ARCHITECTURE.md`, «Проверка кадров»).
- **Холодный старт** (проверен на 0.8): свежий клон → `npm install` → `npm run check` → `npm run shot` — без
  ручных действий, ≈ 13 с.

Настоящего мира (карты, жителей с поведением) ещё нет — это этап 1.

## Как это увидеть

| Что | Как |
|-----|-----|
| Локально | `npm run dev` |
| Заставка с меню | `?scene=title` (сцена по умолчанию); с сохранённым миром — `?scene=title&slot=world&seed=7&ticks=9000` |
| Мир игрока | `?scene=world` — из автосохранения (пусто — новый мир); `?scene=world&slot=world&seed=7&ticks=9000` — заготовка |
| Испорченное сохранение | `?scene=world&slot=broken&seed=7&ticks=9000` (также `slot=alien`, `slot=newer`, `slot=empty`) |
| Сохранения в браузере целиком | `npm run e2e` |
| Прогон из сохранения | `npm run sim -- --load файл.json --years 5` (файл — «Сохранить в файл» в игре) |
| Эталон стиля | `?scene=stylesheet` (целиком), `&zoom=2`, `&zoom=4` (крупно, по центру — костёр) |
| Палитра | `?scene=palette` — ряды, коды, сколько спрайтов используют цвет; перекраска жителей 6 × 5 |
| Таблицы данных | `?scene=data` — ресурсы со значками, земля, баланс с пояснениями |
| Все спрайты | `?scene=gallery` (все анимации, перекраски, тени, атлас) |
| Один спрайт крупно | `?scene=gallery&sprite=man` (или `woman`, `campfire`, `water_shallow`…) |
| Ядро и календарь | `?scene=clock`; пробел — пауза, 1–4 — ×1, ×2, ×5, ×20 |
| Прогоны без графики | `npm run sim` (зёрна 1..100 × 10 лет), `npm run sim -- --seeds 1..20 --years 50`, `--help`; итоги в `out/sim/` |
| Скорость симуляции | `npm run bench` |
| Резкость пикселей | `npm run shot -- --out out/crisp --check-crisp 4 x4="?scene=stylesheet&zoom=4&frame=5&ui=0"` |
| Нет ли регрессий | `npm run shot -- --out out/control --compare docs/screenshots/0.8 title="?scene=title&frame=12" …` |

Параметры адресной строки: `scene`, `seed`, `ticks` (промотать мир до тика N), `speed` (0, 1, 2, 5, 20),
`frame` (замороженный кадр: анимация на моменте N × 100 мс — для одинаковых скриншотов), `ui=0` (без интерфейса и
подписей), `sprite` (галерея: один спрайт), `zoom` (целый масштаб картинки мира 1–4; без него — наибольший, что
помещается), `slot` (отладка: заготовка в слоте автосохранения — `world`, `broken`, `alien`, `newer`, `empty`).
В сцене `world` `seed=`/`ticks=` без `slot=` дают **мир из адреса** — он не читает и не пишет автосохранение. Полезные тики: `tickAt(день, тик_дня)` в `src/sim/calendar.ts`; день 5, полдень = `1740`, ночь дня 8 = `3130`.

## Устройство (кратко)

- `src/main.ts` — запуск: параметры, выбор сцены, цикл кадров (номер кадра показа, 10 в секунду — `PRESENTATION_FPS`);
  отладочный крючок `window.__fc` (`ready`, `errors`, `world`).
- `src/app/` — `params.ts`, `scenes.ts` (реестр), `loop.ts`, `controls.ts`, `dataRefs.ts` (ссылки таблиц на
  графику), `dates.ts` (дата словами); сцены `titleScene` (+ меню `titleMenu.ts`), `worldScene`, `clockScene`
  (`createClockView` — вид мира ядра, им рисует и `world`), `galleryScene`, `paletteScene`, `stylesheetScene`,
  `dataScene`; сохранения в браузере — `saveSlot.ts` (localStorage), `savedGame.ts` (какой мир открыть,
  автосохранение, заготовки `slot=`), `saveFiles.ts` (файлы). Устройство — `ARCHITECTURE.md`, «Сохранения».
- `src/main.ts` загружает игру после того, как готов `window.__fc` (ошибку таблиц видно на странице).
- `src/sim/` — ядро: `world.ts`, `rng.ts`, `calendar.ts`, `events.ts`, `hash.ts`, `math.ts`, `save.ts`
  (сохранения: `saveWorld`, `loadWorld`, `SAVE_VERSION`, `MIGRATIONS`), `systems/`.
- `src/art/` — графика как код: `palette.ts`, `sprite.ts`, `raster.ts`, `atlas.ts`, `registry.ts`, `terrain.ts`
  (виды земли и переходы), `sprites/` (58 файлов, из них 32 значка ресурсов). Чистые функции без браузера.
- `src/data/` — `schema.ts` (проверка схем), `tables.ts` (схемы таблиц, `loadTables`), `index.ts` (`DATA`).
  `data/` — `balance.json`, `resources.json`, `terrain.json`. Устройство и «как добавить» — `ARCHITECTURE.md`,
  «Таблицы данных»; решения — ADR-014.
- `src/render/` — `spriteSheet.ts` (атлас, кадры, тени), `terrainLayer.ts` (земля карты с кешем состояний ряби),
  `scenery.ts` (земля → тени → предметы по глубине → значки).
- `src/sim/stats.ts` (виды показателей и их запись снаружи мира) и `src/sim/metrics.ts` (список показателей).
- `tools/` — `roadmap.ts`, `screenshot.ts`, `e2e.ts` (сквозная проверка), `browser.ts` (сборка, раздача, Chromium —
  общее для двух последних), `png.ts` и `imageChecks.ts` (чтение PNG, резкость и сравнение кадров — для
  `screenshot.ts`), `sim.ts` (прогоны) и `sim/` — `args.ts`, `run.ts` (один мир, новый или загруженный),
  `worker.ts` (поток), `timing.ts` (замер тика), `report.ts` (CSV, JSON, таблица). Устройство, «как добавить
  показатель» и «как читать итог» — `ARCHITECTURE.md`, «Прогоны без графики»; решения — ADR-015.

## Замеры

| Что | Значение | Как измерить |
|-----|----------|--------------|
| **Базовый замер этапа 0:** пустой мир (календарь + светлячки), один поток | тик ≈ 0,3–0,4 мкс (99 % — ≤ 1,5–1,9 мкс), ≈ 500–740 игровых лет/с на мир (шумит от машины: на 0.8 — 495–611) | `npm run bench` |
| Прогон 100 миров × 10 лет, 4 потока | ≈ 0,9–1,3 с, ≈ 770–1 060 игровых лет/с всего | `npm run sim` |
| Прогон 100 миров × 100 лет, 4 потока | ≈ 7,6–8,7 с (≈ 0,17 с на мир; цель GDD — ≤ 30 с на мир с 40 жителями) | `npm run sim -- --years 100` |
| Холодный старт: `npm install` + `npm run check` + 2 кадра | ≈ 13 с | см. отчёт 0.8 |
| Загрузка и проверка всех таблиц | ≈ 53 мкс (Node) | см. отчёт 0.5 |
| Сохранение: размер | 10 лет — 81 КБ, 50 лет — 413 КБ, 200 лет — 1,7 МБ (почти всё — журнал) | см. отчёт 0.7 |
| Сохранение / загрузка мира 200 лет (Node) | ≈ 25 мс / ≈ 27 мс; 10 лет — 1,2 / 1,3 мс | см. отчёт 0.7 |
| Автосохранение в Chromium, мир 200 лет | ≈ 25–30 мс раз в игровой год (из них запись в localStorage ≈ 4 мс) | см. отчёт 0.7 |
| Кадр сцен в Chromium (заставка, эталон ×2/×4, галерея, `clock` ×20) | интервал кадров ровно 16,7 мс, худший 16,8 мс — без пропусков | см. отчёт 0.4 |
| Атлас: 58 спрайтов, 126 кадров + тени, 256×165 | ≈ 9–12 мс | шапка сцены `gallery` |
| Земля эталона 30×18, все 4 состояния ряби | открытие сцены ≈ 0,35 с | см. отчёт 0.4 |
| Земля карты 64×64, все 4 состояния ряби (Node) | ≈ 0,35 с | см. отчёт 0.4 |

## Известные проблемы

- Сцена `clock` рисует небо цветами в коде, мимо палитры — отладочная сцена; решение вместе с суточным светом
  (шаг 1.5, `BACKLOG.md`).
- Ходьба анимируется по времени показа и не ускоряется на ×20 — шаг 1.3 (`BACKLOG.md`).
- Сидячей позы нет: на заставке двое стоят у огня (`BACKLOG.md`).
- Экраны с дробным масштабом (Windows 125 %) — пиксели разной ширины; шаг с камерой (`BACKLOG.md`).
- Журнал событий хранит всю историю без ограничения (`BACKLOG.md`): сохранение мира через 10 лет — 81 КБ, через
  200 лет — 1,7 МБ (15 400 событий). Хранилище браузера (Chromium) вмещает ≈ 5,2 млн знаков — ≈ 600 лет нынешнего
  мира; с картой и жителями это сократится — тогда IndexedDB и/или сжатие (`BACKLOG.md`).
- Сохранения прошлых шагов не открываются после изменения устройства мира («сохранение сделано старой версией») —
  так задумано до этапа 5 (ADR-016). Один слот автосохранения; две вкладки с миром пишут в него по очереди.
- Скорость игры и пауза не сохраняются: после перезагрузки мир идёт на ×1 (`BACKLOG.md`).
- Прогон досчитывает мир до конца срока, даже если в нём все умерли; время тика в многопоточном прогоне шумит
  (для замеров — `npm run bench`) — `BACKLOG.md`.
- Стопки ресурсов и часть сроков порчи — стартовые числа не из GDD (ADR-014); настраиваются на шагах 1.4–1.11.
- Значок «Шкура-накидка» читается слабее остальных; в GDD расходятся материалы шалаша и перечень ресурсов;
  мелкая вода непроходима (броды — позже) — всё в `BACKLOG.md`.
- Владелец ещё не оценил стиль (запрошено на 0.4 и повторно на 0.8) — его отзыв записать в `docs/FEEDBACK.md` и учесть.
- Заставка рисует себя в своём масштабе (наибольший целый, что покрывает окно: на 1280×720 — ×6) и параметр `zoom=`
  не понимает — так задумано; резкость заставки проверяется на её масштабе (`--check-crisp 6`).

## Как устроена работа (важно для каждой сессии)

- Проверок на GitHub (GitHub Actions) и публикации нет и не будет — ADR-011. Проверка — только `npm run check`.
- Свой PR сессия **сливает сама**, не спрашивая владельца (`docs/PROCESS.md`, раздел 5).
