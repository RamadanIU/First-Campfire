# Шаг 2.1 — Анкета жителя и карточка по щелчку

**Дата:** 2026-11-28 · **PR:** см. описание в GitHub (ветка `ccr-d856fbba-setp0w`) · **Решение:** ADR-036

## Что сделано

- **У каждого жителя есть имя.** Имена складываются из слогов «народа первого костра» (новая таблица
  `data/names.json`: корень и окончание своего пола — «Рад» + «омир» = Радомир, «Люб» + «ава» = Любава). Среди живых
  имена не повторяются; неудачные сочетания перечислены в таблице и не даются. В мире 1 живут Зоран и Весана.
- **Возраст идёт вместе с календарём.** Первая пара — молодые взрослые 18–22 лет, рождённые до сотворения мира;
  у каждого свой день рождения в году — в этот день он становится на год старше.
- **Анкета** (GDD §4.1): имя, пол, возраст, дата и место рождения, мать, отец, супруг(а), дети. У первой пары родители
  неизвестны («пришли при сотворении мира»), супругов и детей нет — их принесёт шаг 2.3.
- **Память — 8 последних значимых событий.** Правило ниже; будничное (поел, попил, поспал, принёс ветки) не
  запоминается, а «чуть не умер от голода» — да. Для этого появилось новое событие «чуть не умер»: здоровье упало
  ниже 30 от голода, жажды или холода.
- **Карточка жителя по щелчку** заменила маленькую карточку шага 1.6: портрет (свой спрайт, голова и плечи ×4), имя,
  «мужчина, 22 года», «пришёл при сотворении мира», «Сейчас: подкладывает дрова в костёр» и «Почему: костёр
  прогорает — нужны дрова» (из журнала решений, словами зрителя), пять шкал, семья (родственник — кнопка, щелчок
  открывает его карточку), память с датами. На телефоне — внизу во всю ширину.
- **Лента событий называет жителей по именам**: «Пришла Весана», «Зоран развёл первый костёр».
- Сцена таблиц `?scene=data` показывает набор имён (129 мужских, 173 женских имени); прогоны считают новый
  показатель «Чуть не умерли, раз».

### Правило памяти

Житель запоминает **редкое, что меняет жизнь или запоминается навсегда**:

| Пишем | Кому |
| ----- | ---- |
| Пришёл к стоянке (в день сотворения мира) | пришедшему |
| Развёл первый костёр стоянки | тому, кто развёл |
| Упал без сил — долго не спал | упавшему |
| Чуть не умер от голода / жажды / холода (здоровье ниже 30, пока нужда на нуле) | ему самому, один раз на беду |
| Умер такой-то — причина | всем живым |

**Не пишем:** еду (в том числе «поел впервые»), питьё, сон, работу, костёр погас или разведён не впервые, погоду,
«нужда упала до нуля». Память хранит 8 последних записей (GDD: 5–10). Рождение, союз, смерть родных — строки в
том же правиле на следующих шагах (`memorable` в `src/sim/profile.ts`).

## Проверки

- `npm run check`: зелёный (линтер, типы, тесты, дорожная карта, сборка).
- `npm run e2e`: «Все проверки пройдены» (выбор жителя, карточка целиком, лента по именам, щелчок по строке ленты).
- Прогоны без графики — **история миров не изменилась**: новый поток случайности `profiles` стоит в конце, остальные
  системы получают те же числа; все показатели 100 миров × 10 лет — как на 1.13 (смертей 0, «ошибка ИИ» 0, «Чуть не
  умерли» 0, доли времени 0,20 / 0,30 / 0,50). Отпечатки (меняются законно — новые поля и поток):
  - `npm run sim` (100 × 10 лет) — `c77f10596837c283`, упавших миров нет;
  - `npm run sim -- --years 50` — `4de3a9102cd150f0`; смертей 0, «Чуть не умерли» 0, обмороков 0,22 (мир 86 — 9);
  - `npm run sim -- --seeds 1..20 --years 1 --threads 1` — `3dce31a38a17b25d`, «Пара жива» 1 у всех;
  - `npm run bench` — `eada0d5346cc4cdb`; хэши: зерно 1 `f7783766f2cfcf94`, 2 `48e2f71de56c1ad9`, 3 `d19d50109c7193a7`.
- Производительность: тик 100 × 10 лет — 8,4 мкс в среднем, 99 % ≤ 116 мкс (1.13 — 8,9 / 121); `npm run bench` —
  7,4 мкс, 29 игровых лет/с (1.13 — 7,9). Система памяти смотрит только события текущего тика. Кадр ×2 на ×20 с
  открытой карточкой — 4,8 мс в среднем, 99 % ≤ 9,4 мс (1.13 — 5,1 / 14,6): семья и память пересобираются, только
  когда меняются.
- Контрольные сцены: кадры `1.12/` (ест и пьёт, несёт, мёрзнет, спят) и заставка `art-1/08-title`, эталон ×4
  `art-1/01-style4` (адрес `frame=3`) — **пиксель в пиксель**. «Мир после загрузки» осмотрен: всё то же, лента — по
  именам («Ладко развёл костёр», «Пришла Весуня»).

## Как устроено

- `src/sim/profile.ts` — анкета: тип `Memory`, `firstComer` (анкета пришедшего при сотворении: имя, возраст, день
  рождения — поток `profiles`), `ageOf`, `cameFromOutside`, `addMemory`, правило памяти `memorable(событие)`, система
  `memoriesSystem` — последняя в `SYSTEMS` (раздаёт события тика); `createWorld` вызывает `recallTick` для тика 0.
- `src/sim/names.ts` — `namesOf`, `pickName`; `data/names.json` + схема `namesSchema` в `src/data/tables.ts`
  (`DATA.names`); в `balance.life` — `firstPairAge`, `memorySize`, `nearDeathHealth`.
- `src/sim/life.ts` — событие `villager_nearly_died` при переходе здоровья через `life.nearDeathHealth`.
- События: `villager_arrived` и `villager_died` несут `name`. `SAVE_VERSION` 11 → 12.
- `src/ui/hud.ts` — новая карточка; `HudSource.portrait(житель)` даёт сцена (`portraitCanvas` в
  `src/app/worldScene.ts`). Слова — `CARD`, `memoryText`, `whyOf`, `feedText(событие, { sex, name })` в
  `src/ui/texts.ts`. Стили — `.hud-card*`, `.hud-kin`, `.hud-memory` в `src/ui/style.css`.
- `window.__fc.world.villagers()` отдаёт и `name` (для `npm run e2e`).

## Решения и отступления

- ADR-036: первая пара рождена до сотворения мира (отрицательный тик рождения); память — отражение журнала по одному
  правилу; имя в событиях прихода и смерти; первая пара — не супруги (пара образуется на 2.3).
- «Почему» в карточке — не числа разума (они в `debug=mind`), а причина словами по занятию плана и текущим шкалам.
- В карточке нет биографии строками (GDD §11.4 «биография в 5–10 строк из памяти») — это летопись и биографии шага 2.10;
  память показывается списком.

## Известные проблемы и что отложено

- Смерть жителя помнят все живые → сузить до родни и знакомых на 2.2 (`BACKLOG.md`).
- Щелчок по родственнику работает, но родни пока ни у кого нет — в браузере не проверен → проверка вписана в
  карточку 2.3.
- Анкеты умерших хранятся только в журнале (имя, пол, причина) — карточка умершего короткая → архив — 2.8 или 2.10.
- Некоторые имена звучат странно («Ладко», «Силим») — `skip` в `data/names.json` пополняется без кода.

## Подсказки следующему шагу

- 2.2 (отношения): блок «Отношения» в карточке — рядом с «Семьёй», тем же приёмом (`kinButton`, пересборка по ключу).
  Новые занятия (разговор, досуг) — ветки в `whyOf` и `doingOf`; новые значимые события — строка в `memorable`.
- «Химия» пары — своя случайность: поток в конце `RNG_STREAMS` (после `profiles`).
