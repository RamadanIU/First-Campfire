# Шаг 0.6 — Прогоны без графики и сбор статистики

**Дата:** 2026-11-17 · **PR:** #7

## Что сделано

- **Команда `npm run sim`** — главный инструмент баланса: проигрывает много миров без экрана, по нескольку
  одновременно (потоки по числу ядер), показывает прогресс и в конце печатает таблицу итогов. Параметры:
  `--seeds 1..100` (или `1,2,5`, `1..10,50`), `--years N`, `--threads N`, `--out папка`, `--help`.
- **Показатели мира** — список `src/sim/metrics.ts`, **одна строка на показатель**: сколько событий, сумма,
  среднее, максимум, минимум по событиям журнала (с фильтром) или число из состояния мира. Для каждого мира —
  итог за весь прогон и **срез за каждый игровой год**. Пока считается то, что есть: события, ночи, рои светлячков.
- **Итог прогона**: таблица в консоли (среднее, минимум и максимум по мирам; в скобках — зерно мира с крайним
  значением, чтобы его можно было открыть), `worlds.csv` (строка на мир), `years.csv` (строка на мир и год — для
  кривых «по годам»), `summary.json` (сводка, кривые по годам, ошибки).
- **Время тика в каждом прогоне**: среднее, «99 % тиков не дольше» и худший тик, скорость в игровых годах в
  секунду — и по миру, и по году. Из каждого тика вычитается цена самого замера.
- **Итог воспроизводим**: повторный запуск — побайтно те же CSV (кроме столбцов времени), **при любом числе
  потоков**. «Отпечаток прогона» — один хэш всех миров: по нему видно, изменилась ли история хоть одного.
- **Упавший мир не роняет прогон**: в итоге — строка `error`, зерно, тик и место ошибки; код выхода 1.
- **`npm run bench` влит в `npm run sim`** — теперь это готовая настройка (3 мира × 200 лет на одном потоке);
  отдельного кода замера больше нет.

## Проверки

- `npm run check`: зелёный — линтер, типы, **388 тестов в 30 файлах** (было 349 в 24), дорожная карта, сборка.
- Контрольные сцены (заставка, эталон ×2 и ×4, палитра, галерея, таблицы, житель крупно, часы днём и ночью) сняты
  без ошибок на страницах и просмотрены — как до шага (код отрисовки не менялся).
- **История миров не изменилась**: хэши шага 0.2 (`be967270c8e90d4b`, `c108a8664f8be2d0`, `a45c4d8d8bf9e8ae`) те же.
  Выяснилось, что старый `npm run bench` считал их на 1 020 000 тиках (20 000 тиков разогрева на том же мире), а
  не на 1 000 000, как было записано, — в `STATUS.md` исправлено, новые эталоны — на ровных 200 годах.
- Ошибочные пути проверены вручную (временной правкой потока, затем файл возвращён): мир, бросивший ошибку на
  первом году, — строка `ОШИБКА`, «зерно 2, тик 4800: …», остальные миры досчитаны, код выхода 1; поток, упавший
  целиком, заменяется новым, его мир помечен ошибкой. Неверные параметры — сообщение, справка, код 2 (тест).

### Производительность

- Тик симуляции не менялся: запись показателей идёт снаружи мира, после тика, и в время тика не входит.
- Накладные расходы прогона на пустом мире заметны: ≈ 0,3 мкс на тик (два отсчёта часов, гистограмма, запись
  показателей) при самом тике ≈ 0,3 мкс — общая скорость по часам на одном потоке ≈ 340–380 лет/с против
  ≈ 610–710 лет/с чистого счёта (`npm run bench`). С жителями (тик — десятки микросекунд и больше) это доли процента.

## Как устроено

- `src/sim/stats.ts` — виды показателей (`gauge`, `count`, `sum`, `mean`, `max`, `min`), `checkMetrics`, запись:
  `createStats(world, metrics)` → `recordTick(stats, world)` после каждого тика → `finishStats` (итог и срезы по
  годам). Читает только новые события журнала (по id). Мир не меняет.
- `src/sim/metrics.ts` — список `METRICS` (8 показателей).
- `tools/sim.ts` — команда: потоки, очередь зёрен, прогресс (в терминале — одна строка, в логе — каждые 10 %),
  файлы, таблица, код выхода.
- `tools/sim/` — `args.ts` (параметры и справка), `worker.ts` (поток), `run.ts` (`runWorld`, `warmUp`),
  `timing.ts` (замер тика, гистограмма), `report.ts` (CSV, сводка, таблица, `TIMING_COLUMNS`, `dropColumns`).
- Тесты: `src/sim/stats.test.ts` (показатели сходятся с журналом, рубеж года, пустые значения, запись с середины
  истории, мир не меняется), `tools/sim/*.test.ts` (параметры, замер, один мир, итоговые файлы и таблица),
  `tests/sim.test.ts` (настоящая команда: воспроизводимость, независимость от числа потоков, вывод, ошибки параметров).
- `package.json`: `sim`, `bench` (настройка `sim`); `tools/bench.ts` удалён.
- Подробно: `docs/ARCHITECTURE.md`, «Прогоны без графики».

## Решения и отступления

- **ADR-015**: показатели записываются вне мира (не меняют историю, хэш и сохранения); агрегаты по событиям +
  `gauge`; срез за год — значения этого года; потоки `worker_threads` с очередью; замер каждого тика с вычитанием
  цены замера; `bench` — настройка `sim`.
- Сверх карточки: «99 % тиков не дольше» (худший тик обычно — пауза сборки мусора, а не игра), зерно мира с
  крайним значением в таблице, отпечаток прогона, `--threads`, `--help`, обработка упавших миров и потоков.
- Год в срезе — шаги `from+1 … to`: событие на самом рубеже (тик 4 800, «весна второго года») относится к
  закончившемуся году. Так строка года — это «что сделали 4 800 шагов и каким стал мир после них».
- `npm run sim` по умолчанию — зёрна `1..100`, 10 лет (как в карточке и GDD: «сто миров»).
- Картинка `03-sim-table.png` отрисована небольшим скриптом из настоящего текста вывода (Playwright, не в
  репозитории): `npm run shot` снимает только страницы игры, а новое в шаге — вывод консоли.

## Известные проблемы и что отложено

- Время тика в многопоточном прогоне шумит (первые миры потока, общие ядра, сборка мусора) — для замеров есть
  `npm run bench`; запись в `BACKLOG.md`.
- Прогон досчитывает мир до конца срока, даже если все умерли (условие конца мира и статус `extinct`) — шаг 1.10
  или 1.13, `BACKLOG.md`.
- Идеи в `BACKLOG.md`: сравнение двух прогонов «было → стало» (`--compare`), вид показателя «среднее за год по дням».
- Третья своя функция русских окончаний (`plural`) — в `tools/sim/report.ts`; запись в `BACKLOG.md` дополнена.
- Показатели «Событий» и «Записей в журнале» пока совпадают (журнал хранит всю историю); разойдутся, когда журнал
  ограничат. «Записей в журнале» по годам показывает его рост (≈ 77 записей в год).
