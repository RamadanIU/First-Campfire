# Шаг 0.2 — Ядро симуляции: тики, случайность, календарь

**Дата:** 2026-11-16 · **PR:** #2

## Что сделано

- У игры появилось «сердце»: мир, который шагает тиками. Одно зерно всегда даёт одну и ту же историю —
  это доказано тестами (одинаковый «отпечаток» мира после 10 000 тиков).
- Генератор случайных чисел с отдельным потоком для каждой системы: новая система не сдвигает историю старых.
- Календарь по GDD: сутки 400 тиков (рассвет, день, закат, ночь), сезон 3 дня, год 12 дней.
- Журнал событий: всё заметное записывается вместе с причиной («вылетели светлячки» ← «наступила ночь»).
- Игровой цикл: 10 тиков в секунду на ×1, скорости пауза / ×1 / ×2 / ×5 / ×20, защита от зависания на медленном
  компьютере, плавность движения между тиками.
- Отладочная сцена `clock`: небо меняется по времени суток (розовый рассвет, день, золотой закат, ночь с луной
  и звёздами), на экране дата, время, тик, скорость и последние события журнала. Ночью над лугом летают
  светлячки — временная «проверочная» система со случайностью.
- Параметры адресной строки `ticks=` (промотать мир до нужного тика) и `speed=`.

## Проверки

- `npm run check`: зелёный — линтер, типы, 70 тестов в 11 файлах, дорожная карта, сборка.
- Производительность (Node 22, Xeon 2,1 ГГц, контейнер сессии): `npm run bench` — пустой мир (календарь +
  светлячки) **≈ 2,2–2,8 млн тиков в секунду** (0,35–0,46 мкс на тик), то есть ≈ 450–590 игровых лет в секунду.
  Хэши повторяются от запуска к запуску: зерно 1 → `be967270c8e90d4b` после 1 020 000 тиков.
- Кадр сцены `clock` в Chromium при ×20 (симуляция + отрисовка + надписи): в среднем 1,0 мс, 95 % кадров ≤ 1,3 мс,
  худший 4,3 мс — при бюджете 16 мс.
- Детерминированный логарифм `ln` сверен с `Math.log` на 6 000 значений: расхождение не больше 4·10⁻¹⁶.
- Генератор сверен с эталонной реализацией sfc32 на 100 000 чисел.
- Сцена на телефоне (390×844) проверена отдельным кадром: сцена подстраивается под узкий экран, ничего не обрезано.
- Прогоны `npm run sim` — с шага 0.6.

## Как устроено

- `src/sim/world.ts` — `World`, `createWorld(seed)`, `stepWorld`, `runTicks`; список систем `SYSTEMS` и потоков
  случайности `RNG_STREAMS`.
- `src/sim/rng.ts` — генератор; `calendar.ts` — время; `events.ts` — журнал; `hash.ts` — отпечаток мира;
  `math.ts` — точная математика; `systems/calendarEvents.ts`, `systems/fireflies.ts` — системы.
- `src/app/loop.ts` — игровой цикл (`createGameLoop`), `src/app/controls.ts` — клавиши скорости,
  `src/app/clockScene.ts` — сцена. У сцены появился необязательный метод `update(мс)`; `src/main.ts` вызывает его
  каждый кадр (кроме режима `frame=`).
- `tools/bench.ts` (`npm run bench`) — замер скорости пустого мира.
- Подробности и «как добавить систему» — `docs/ARCHITECTURE.md`, разделы «Ядро симуляции» и «Игровой цикл».

## Решения и отступления

- ADR-008: генератор sfc32 с именованными потоками.
- ADR-009: в симуляции запрещены неточные функции `Math` и `**` (они могут различаться между браузерами);
  свой логарифм в `src/sim/math.ts`. Правило добавлено в архитектурный тест.
- ADR-010: сутки начинаются с рассвета; тик 0 — сотворение мира; журнал событий с причинами.
- Сверх карточки, но в её духе: в генераторе есть ещё `weightedIndex` и `shuffle` (понадобятся ИИ жителей);
  `npm run bench` для замера; сцена `clock` показывает журнал событий с причинами — так видно, что причинность работает.

## Известные проблемы и что отложено

- Цвета неба в `clock` заданы в коде, мимо палитры (как у заставки) — до шага 0.4 (`BACKLOG.md`).
- Журнал событий хранит всю историю; ограничение — позже (`BACKLOG.md`).
- Тексты сцены `clock` пока прямо в её файле; единый модуль текстов появится с HUD (`BACKLOG.md`).
- Проверки GitHub Actions по-прежнему не запускаются из-за блокировки аккаунта (см. `STATUS.md`).
