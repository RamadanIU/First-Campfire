# Шаг 0.8 — Ревизия этапа 0

**Дата:** 2026-11-17 · **PR:** #9

## Что сделано

- **Фундамент перепроверен целиком.** Все критерии шагов 0.1–0.7 прогнаны заново на текущей сборке (таблица ниже) —
  всё выполнено, ничего не сломалось. Все контрольные кадры совпали с прежними **пиксель в пиксель** (кроме двух
  законных отличий — см. «Проверки»).
- **Холодный старт работает**: свежая копия проекта → `npm install` → `npm run check` → `npm run shot` — без единого
  ручного действия, за 13 секунд; кадры свежей копии совпадают с эталонными.
- **Проверка кадров одной командой** (новое в инструментах): `npm run shot -- --check-crisp N` доказывает, что
  пиксели резкие на ×N, `--compare папка` сравнивает кадры с прежними пиксель в пиксель. Раньше это делали разовыми
  скриптами, которые не попадали в репозиторий; теперь любая сессия повторит проверку. Пригодится сразу: шаги 1.1
  и 1.2 требуют резкости карты на всех масштабах.
- **Светлячки оставлены до ревизии этапа 1** (ADR-017): оказалось, что это единственная случайность в мире, и на ней
  держатся тесты детерминизма, сохранений и статистики. Убрать их сейчас значило бы ослабить проверки. В карточке
  1.13 записан полный перечень, что затронуть при удалении.
- **Карточки этапа 1 уточнены по реальному коду**: что уже готово и где лежит (спрайты, свет костра на заставке,
  слой земли, сцена `world`, параметр `zoom=`, клавиши скорости), что обязательно сделать попутно (форма мира и версия
  сохранения, свой поток случайности, модуль текстов с перечнем строк, `devicePixelRatio`, кадр ходьбы по пути,
  конец мира в прогонах, «умер при доступной еде»), какие решения принять («охапка дров» — какой ресурс).
- **Отложенное разобрано**: закрытые записи убраны, каждая открытая указывает на конкретный шаг (большинство — вписаны
  в карточки этапа 1); мёртвого кода не найдено.
- **Базовые замеры скорости** этапа 0 записаны в `STATUS.md`.

## Как устроено

- `tools/png.ts` — `decodePng(байты)` → `{ width, height, data }` (RGBA): 8 бит, RGB/RGBA, без чересстрочности;
  неподдержанное — понятная ошибка. Без библиотек: `zlib` из Node и пять фильтров строк PNG.
- `tools/imageChecks.ts` — `crispness(картинка, N)` (лучший сдвиг сетки, число смешанных квадратов, первый из них) и
  `compareImages(a, b)` (число отличающихся пикселей и рамка вокруг них). Чистые функции, тесты рядом.
- `tools/screenshot.ts` — опции `--check-crisp N` (размытый кадр роняет команду) и `--compare папка` (кадр того же
  имени, номер `NN-` не важен; отличия только сообщаются). Описание — `ARCHITECTURE.md`, «Проверка кадров».
- Документы: `docs/roadmap/stage-01.md` (уточнения), `ARCHITECTURE.md`, `STATUS.md`, `BACKLOG.md`, ADR-017.

## Решения и отступления

- **ADR-017**: светлячки остаются до ревизии 1.13 — карточка разрешала оставить их, «если нужны»; они нужны тестам.
  Проверка кадров — опциями `npm run shot`, без зависимостей.
- Карточка требовала перепроверить шаги 0.2–0.7; перепроверен и 0.1 (три пункта — дёшево).
- Критерии 0.3 и 0.5 («добавляется одним файлом / строкой», «ошибка ловится тестом») проверены **вживую** —
  временным спрайтом и временной записью, а не только чтением тестов; временные файлы убраны.
- Прогоны: цель ревизии «подстроить числа в `data/`» к этапу 0 неприменима — жителей нет; прогон на 100 зёрнах
  (больше 20 по регламенту) записан как база для сравнения.
- Поиск мёртвого кода: все экспорты `src/` и `tools/` проверены на использование вне своего файла — неиспользуемых нет
  (экспорты «только для тестов» — это функции библиотек, которые этап 1 начнёт применять: `shuffle`, `cloneRng`,
  `optional`).

## Известные проблемы и что отложено

- Владелец ещё не оценил стиль эпохи 0 — вопрос повторён (`BACKLOG.md`, «Вопросы владельцу»).
- Все открытые записи `BACKLOG.md` получили конкретный шаг; новая идея — `npm run control` (контрольные сцены
  одной командой из файла-перечня), если ручной перечень станет мешать.
- Заставка рисует себя в своём масштабе (×6 на 1280×720) и `zoom=` не понимает — так задумано (записано в `STATUS.md`).
