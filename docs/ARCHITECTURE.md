# Архитектура

Документ описывает, как устроен код и какие правила нельзя нарушать. Он должен соответствовать реальному коду:
изменил устройство — обнови документ в том же PR. Обоснования решений — в [`DECISIONS.md`](DECISIONS.md).

## Технологии

| Что                     | Чем                                                       | Примечание                                                              |
| ----------------------- | --------------------------------------------------------- | ----------------------------------------------------------------------- |
| Язык                    | TypeScript (строгий режим)                                | Только «стираемый» синтаксис: Node запускает `.ts` напрямую, без сборки |
| Сборка и dev-сервер     | Vite                                                      | `npm run dev`, `npm run build` → `dist/`                                |
| Отрисовка               | Canvas 2D, собственный лёгкий рендерер                    | Без движка; см. ADR-002                                                 |
| Интерфейс               | HTML/CSS поверх холста                                    | `#ui` в `index.html`                                                    |
| Звук                    | Web Audio, процедурный синтез                             | Появится на этапе 5                                                     |
| Тесты                   | Vitest                                                    | `*.test.ts` рядом с кодом, сценарные — в `tests/`                       |
| Линтер и форматирование | Biome                                                     | `npm run lint`, `npm run format`                                        |
| Скриншоты               | Playwright + Chromium (предустановлены в облачной сессии) | `tools/screenshot.ts`; в `package.json` не добавлять                    |
| Проверки                | `npm run check` в сессии                                  | GitHub Actions не используется (ADR-011)                                |
| Публикация              | Нет                                                       | GitHub Pages не используется (ADR-011)                                  |

Библиотек времени выполнения нет, и по умолчанию они не добавляются. Нужна зависимость — запись в `DECISIONS.md`.

## Структура каталогов

```
data/            таблицы содержания и баланса (*.json): ресурсы, здания, технологии, черты, сценки…
src/
  sim/           СИМУЛЯЦИЯ: состояние мира и системы. Чистая, детерминированная, без браузера
  data/          типы таблиц, их загрузка и проверка
  art/           графика как код: палитра, описания спрайтов, растеризатор, атлас
  render/        отрисовка мира на Canvas 2D: камера, тайлы, спрайты, свет, частицы
  ui/            интерфейс наблюдателя (HTML/CSS): панель, карточки, летопись, слои
  app/           запуск: параметры адресной строки, сцены, игровой цикл, ввод
  main.ts        точка входа
tools/           скрипты Node: дорожная карта, скриншоты, прогоны без графики
tests/           сквозные тесты: архитектурные правила, детерминизм, сценарии
docs/            вся документация проекта (см. docs/PROCESS.md, «Где что лежит»)
```

Направление зависимостей — строго в одну сторону:

```
app → ui, render → art
app, ui, render → sim → data
```

`sim` и `data` не импортируют ничего из `render`, `ui`, `app`, `art`. Это проверяет `tests/architecture.test.ts`.

## Правила, которые нельзя нарушать

### 1. Детерминизм: одно зерно — одна история

- Вся случайность — только через генератор случайных чисел симуляции, состояние которого хранится в мире.
  `Math.random`, `Date`, `performance.now`, таймеры в `src/sim` запрещены (проверяется тестом).
- Время симуляции — это номер тика. Скорость игры меняет число тиков в секунду, но не результат.
- Порядок обхода сущностей фиксирован (массивы, сортировка по id). Результат не должен зависеть от порядка
  вставки в `Map`/`Set`, от кадровой частоты, от размера окна, от положения камеры.
- У каждой системы свой именованный поток случайных чисел, чтобы новая система не сдвигала историю остальных
  сильнее необходимого.
- Тест детерминизма сравнивает хэш состояния двух прогонов одного зерна. Если он упал — ищи источник
  недетерминизма; править сам тест нельзя.
- **Только точная математика.** `Math.sin`, `Math.cos`, `Math.exp`, `Math.log`, `Math.pow`, `**` и подобные
  стандарт разрешает вычислять приближённо, и в разных браузерах последний бит может различаться — этого хватит,
  чтобы истории одного зерна разошлись. В `src/sim` разрешены только `+ − × ÷`, `Math.sqrt`, округления,
  `Math.min/max/abs/imul` и функции из `src/sim/math.ts` (там, например, свой `ln`). Проверяется тестом.
- Уровни детализации (GDD §2.4) не должны менять историю в зависимости от того, куда смотрит камера:
  упрощение определяется правилами симуляции, а не экраном. Решение об этом принимается на шаге 6.11.

### 2. Симуляция отдельно от отрисовки

- `src/sim` ничего не знает об экране. Та же симуляция работает в Node без графики (`npm run sim`) —
  это главный инструмент баланса.
- Отрисовка и интерфейс только **читают** состояние. Никакая игровая логика не живёт в `render`/`ui`.
- Плавность движения — интерполяция в отрисовке между двумя тиками, а не дробные тики в симуляции.
- Симуляция сообщает о происходящем через **журнал событий** (рождение, смерть, открытие, начало стройки…).
  Из него питаются летопись, звук, пузырьки, сценки, статистика.

### 3. Содержание — в таблицах данных

- Ресурсы, здания, технологии, черты, профессии, сценки, числа баланса — в `data/*.json`.
  В коде — механики, а не списки содержания. Критерий: новый ресурс или новое здание существующего типа
  добавляется строкой в таблице, без правки кода.
- Таблицы проверяются при загрузке и тестами: типы полей, обязательные поля, ссылки между таблицами.
  Ошибка в таблице должна называть файл, запись и поле.
- Идентификаторы в данных — `snake_case` латиницей (`berry_bush`). Названия для игрока — по-русски, отдельным полем.

### 4. Причинность

- У каждого события, решения, постройки, закона хранится **причина** (ссылка на событие или нужду, которые к нему привели).
  Наблюдатель всегда должен иметь возможность получить ответ на вопрос «почему?» (GDD, столп 1).
- Ничего не происходит «по таймеру сценария». Режиссёр событий только сдвигает вероятности.
- Каждый житель ведёт короткий журнал решений (что выбрал и почему) — он нужен для отладки и для поиска
  «нелепых смертей» в прогонах.

### 5. Физичность

- Ресурсы — физические предметы: лежат на тайле, в куче, в хранилище или в руках. Ничего не телепортируется
  и не возникает из воздуха; количество предметов сохраняется (это проверяется тестами-инвариантами).
- Труд виден: у каждого действия есть место, длительность и анимация.

### 6. Каждая технология видна на экране

Технология без видимого проявления (предмет, здание, анимация, деталь одежды, изменение ландшафта) не принимается (GDD §7.5).

### 7. Состояние мира — простые данные

- Мир — обычные объекты, массивы и типизированные массивы, которые целиком сериализуются (сохранение, хэш, снимки
  для таймлапса). Без классов с поведением внутри состояния, без замыканий, без ссылок на DOM.
- Ссылки между сущностями — по числовым id, а не по указателям.
- У сохранения есть номер версии формата. С этапа 5 старые сохранения обязаны открываться (миграции).

### 8. Воспроизводимость экрана

- Любое состояние игры достижимо адресной строкой: `?scene=…&seed=…&ticks=…&cam=x,y&zoom=…&ui=0`.
  Это основа скриншотов и отчётов об ошибках. Новая сцена или режим — значит, новый параметр.
- Сцены регистрируются в `src/app/scenes.ts`. Отладочные сцены (галерея спрайтов, палитра, песочницы) — тоже сцены.
  Параметры конкретных сцен тоже живут в `src/app/params.ts` (например, `sprite=` галереи, `zoom=` — целый
  масштаб картинки мира 1–4; шаг 1.2 сделает его масштабом камеры).
- Страница сообщает о готовности через `window.__fc.ready` и об ошибках через `window.__fc.errors` —
  на это опирается `tools/screenshot.ts`.

### 9. Производительность — с первого дня

Целевые бюджеты (уточняются ревизиями этапов):

| Показатель                              | Цель                          |
| --------------------------------------- | ----------------------------- |
| Тик симуляции при 100 жителях           | ≤ 1 мс                        |
| Тик симуляции при 1500 жителях          | ≤ 8 мс (иначе ×20 невозможна) |
| Кадр отрисовки                          | ≤ 16 мс на среднем компьютере |
| Прогон без графики: 100 лет, 40 жителей | ≤ 30 с на зерно               |

Меряй, а не угадывай. Замеры — в отчёте шага и в `STATUS.md`. Скорость пустого мира без графики:
`npm run bench` (тиков в секунду, игровых лет в секунду и хэш мира на каждое зерно).

## Ядро симуляции

Появилось на шаге 0.2. Всё лежит в `src/sim/`.

| Модуль | Что делает |
|--------|------------|
| `world.ts` | Состояние мира `World` и шаг `stepWorld`. `createWorld(seed)`, `runTicks(world, n)`. Список систем `SYSTEMS` и потоков случайности `RNG_STREAMS` |
| `rng.ts` | Генератор случайных чисел sfc32: состояние — четыре числа, хранится в мире. `intRange`, `floatRange`, `chance`, `pick`, `weightedIndex`, `shuffle`, `normal` |
| `calendar.ts` | Константы времени `TIME` (GDD §13.1) и `calendarAt(tick)` → год, сезон, день, фаза суток, доля фазы |
| `events.ts` | Журнал событий: `emit(world, событие, причина)`, `findEvent`, `eventsThisTick`. Типы событий — объединение `EventBody` |
| `hash.ts` | `hashState(значение)` — стабильный 64-битный отпечаток простых данных; заодно проверяет, что в состоянии нет «непростых» значений |
| `math.ts` | Детерминированная математика: `ln`, `clamp` |
| `systems/` | Системы мира. Сейчас: `calendarEvents` (пишет в журнал смену фаз, сезонов, лет) и `fireflies` (временная проверочная система) |

**Тик.** `world.tick` — сколько тиков уже прошло; тик 0 — момент сотворения (рассвет первого дня весны первого года).
`stepWorld` сначала увеличивает `tick`, потом вызывает системы в порядке `SYSTEMS` — системы видят новый тик.
Порядок систем — часть правил мира: переставлять нельзя, новая система добавляется осознанно.

**Как добавить систему.** Файл `src/sim/systems/<имя>.ts` экспортирует объект `System` (`id`, `step(world)`).
Её состояние — поле в `World` (простые данные) с начальным значением в `createWorld`. Если нужна случайность —
новое имя в конец `RNG_STREAMS` и `world.rng.<имя>`: поток выводится из пары «зерно + имя», поэтому новая система
не меняет числа, которые получают остальные. Затем систему ставят в `SYSTEMS` и пишут тест.

**События и причины.** Каждое событие — `{ id, tick, type, cause, …данные }`. Причина (`cause`) — либо закон
мира (`{ kind: 'rule', rule: 'calendar' }`), либо другое событие журнала (`{ kind: 'event', event: id }`).
Новые виды причин (нужда, решение жителя) добавляются в тип `Cause`. Системы узнают о случившемся в этот тик
через `eventsThisTick(world, тип)` и ссылаются на него как на причину своих событий. Журнал пока хранит всю
историю (≈ 6–7 событий в игровой день); ограничение и архив — когда понадобится (см. `BACKLOG.md`).

**Случайность.** Функции `rng.ts` по возможности тратят одинаковое число выборок (например, `chance` тянет число
даже при p = 0), чтобы подстройка вероятности не сдвигала остальной поток. Эталонный тест в `rng.test.ts`
фиксирует первые числа генератора: если он упал — изменился алгоритм, а значит, все истории.

## Игровой цикл

`src/app/loop.ts` — фиксированный шаг симуляции. Реальное время между кадрами переводится в целые тики:
10 тиков в секунду на ×1 (`TIME.ticksPerSecond`). Скорости `SPEEDS`: пауза, ×1, ×2, ×5, ×20.
Число тиков зависит только от прошедшего времени, а не от частоты кадров.

- **Защита от «спирали смерти».** Один кадр засчитывается не больше чем за 250 мс реального времени
  (фоновая вкладка не вызывает лавину тиков), а на расчёт тиков в кадре отводится не больше 30 мс.
  Не уместившиеся тики отбрасываются — мир замедляется, а не вешает страницу; `loop.lagging` сообщает об этом.
- **Интерполяция.** `loop.alpha` (0…1) — насколько реальное время продвинулось к следующему тику. Отрисовка
  показывает состояние между предыдущим и текущим тиком: например, у светлячка есть `prevX` и `x`.
- **Сцена с миром** (`Scene.update`) крутит свой цикл; `src/main.ts` передаёт ей время кадра. В режиме
  `frame=` (замороженный кадр) `update` не вызывается — мир стоит ровно на тике из `ticks=`.
- Клавиши скорости — `src/app/controls.ts`: пробел — пауза, 1–4 — ×1, ×2, ×5, ×20.

## Графика

Появилась на шаге 0.3, эталон стиля и мастер-палитра — шаг 0.4. Подробно — [`ART.md`](ART.md): формат спрайта,
палитра, как добавить спрайт, правила стиля, земля и переходы, тени, жители. Решения — ADR-012, ADR-013.

- Проекция ¾ сверху, тайл 16×16, взрослый житель 12×18, целочисленный масштаб, сглаживание выключено (GDD §10.1).
- **Графика — это код**: спрайт — текстовая сетка символов и легенда «символ → цвет палитры» (`ряд.номер`),
  один файл `src/art/sprites/<имя>.ts` на спрайт. Список спрайтов (`src/art/registry.ts`) собирается из папки
  автоматически (`import.meta.glob` — работает в Vite и Vitest; простым скриптам Node из `tools/` он недоступен).
- Все цвета — из палитры `src/art/palette.ts`. Цвет «мимо палитры», строка не той длины, символ без легенды,
  повтор имени — ошибки, которые ловит `src/art/sprites.test.ts` с указанием кадра, строки и столбца.
- Перекраска (тон кожи, цвет волос, позже сезон, эпоха, краска) — подмена целого ряда палитры другим рядом той же длины.
- **Земля** рисуется без тайлов-переходов: у вида земли есть слой, высокий заходит на низкий неровным краем,
  посчитанным по мировым координатам (`src/art/terrain.ts`). **Тени** — эллипсы под объектами одним слоем.

| Модуль | Что делает |
|--------|------------|
| `src/art/palette.ts` | Ряды цветов `RAMPS` (мастер-палитра), палитра `PALETTE`, `resolveColor`, `resolveAlpha`, проверка палитры и подмен, `swapKey` |
| `src/art/sprite.ts` | `SpriteDef`, `defineSprite`, `parseGrid`, `frameAt` (кадр по времени), `validateSprite`; тень: `ShadowDef`, `shadowMask`, `shadowOrigin` |
| `src/art/raster.ts` | `rasterizeSprite(спрайт, палитра, подмена?)` → кадры RGBA и тень; `rasterizeShadow`. Чистые функции |
| `src/art/atlas.ts` | `packRects` (полочная упаковка, зазор 1 пиксель), `buildAtlas` → пиксели атласа, прямоугольники кадров и теней |
| `src/art/terrain.ts` | Виды земли `TERRAIN_LOOKS`, `prepareTerrain`, `composeTerrainTile` (тайл с переходами), `variationAt`, `terrainFrameAt`, `terrainStateKey`, `terrainStateTimes` |
| `src/render/spriteSheet.ts` | `createSpriteSheet`: атлас на холсте; `draw(ctx, имя, x, y, {animation, frame / timeMs, scale, swap})` ставит точку привязки в (x, y); `drawShadow`; перекрашенные варианты собираются при первом обращении и кешируются |
| `src/render/terrainLayer.ts` | `createTerrainLayer`: вся земля карты одним холстом на каждое состояние ряби, `composeAll()` — собрать заранее |
| `src/render/scenery.ts` | `createScenery`: земля → слой теней → предметы по глубине (`drawOrder`) → значки |

Направление зависимостей: `app → render → art`. `src/art` — чистые функции без браузера (тесты в Node), холст —
только в `src/render`; это проверяет `tests/architecture.test.ts`.

**Время показа.** `src/main.ts` передаёт сцене номер кадра показа: 10 в секунду (`PRESENTATION_FPS` в
`src/app/scene.ts`). Анимации спрайтов переводят его во время (`frame × 100 мс`) и выбирают кадр по длительностям,
поэтому `?frame=N` всегда даёт одну и ту же картинку. Это время показа, а не время симуляции: анимация не влияет
на мир.

## Тексты

Все строки, которые видит игрок, — по-русски и проходят через единый модуль текстов (появится вместе с HUD),
чтобы на шаге локализации их не пришлось вылавливать по коду.

## Тестирование

| Вид            | Где                          | Что проверяет                                                                |
| -------------- | ---------------------------- | ---------------------------------------------------------------------------- |
| Модульные      | `src/**/*.test.ts`           | Отдельные функции и системы                                                  |
| Архитектурные  | `tests/architecture.test.ts` | Чистота `src/sim` и `src/data`; `src/art` без браузера и чужих модулей       |
| Детерминизм    | `tests/determinism.test.ts`  | Одинаковый хэш мира для одного зерна; сохранение/загрузка не меняют историю  |
| Сценарные      | `tests/`                     | Маленький мир + условие: «двое не умирают неделю», «голодный бросает работу» |
| Инварианты     | `tests/`                     | Сохранение количества предметов, отсутствие жителей в воде и т. п.           |
| Статистические | `npm run sim`                | Сотни миров без графики: выживаемость, темп, причины смертей (GDD §15.2)     |
| Визуальные     | `npm run shot`               | Страница без ошибок + просмотр кадров глазами                                |

Сценарный тест — основной способ закрепить критерий готовности шага: он остаётся в наборе навсегда и не даёт
будущим шагам сломать поведение.
