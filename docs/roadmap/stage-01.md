# Этап 1. Двое у костра

**Цель этапа.** Два человека выживают в маленьком лесу, и на это уже любопытно смотреть: они ищут еду и воду,
спят ночью, собирают ветки, жгут костёр, мёрзнут зимой.

**Проверка этапа.** Посторонний человек смотрит пять минут и верно пересказывает, что происходило (GDD §14.3).

**Важно для всего этапа.**

- Карта пока простая, 64×64. Настоящая генерация мира — этап 5.
- Огонь, сбор, костёр доступны с самого начала. Открытие их как технологий появится на этапе 4 —
  пиши системы так, чтобы «умеет / не умеет» потом можно было включить одним условием.
- Каждое поведение закрепляй сценарным тестом в `tests/`: маленькая карта + условие.
- Числа — из GDD §4.2 и §13, хранятся в `data/` (с шага 0.5: `data/balance.json` — новый раздел или поле в схеме
  `src/data/tables.ts`; ресурсы — `data/resources.json`, земля — `data/terrain.json`; как добавить — `docs/ARCHITECTURE.md`,
  «Таблицы данных»). Сцена `data` показывает загруженные таблицы.
- Показатель для прогонов — строка в `src/sim/metrics.ts` (обычно из события журнала: `count`, `mean`… —
  `docs/ARCHITECTURE.md`, «Прогоны без графики»). Пороги вида «70 % из 20 зёрен» проверяются `npm run sim`;
  в отчёт шага — команда и таблица итогов.
- **Каждое новое поле или система мира меняет его форму**: поднять `SAVE_VERSION` и обновить форму в
  `src/sim/save.test.ts` (упавший тест печатает новую форму и порядок действий; `docs/ARCHITECTURE.md`,
  «Сохранения»). Хэши миров и отпечатки `npm run bench` / `npm run sim` при этом меняются законно — записать
  новые в отчёт и в `STATUS.md` («Контрольный прогон», «Контрольная загрузка»).
- **Новая система со случайностью** — своё имя в конец `RNG_STREAMS` (`src/sim/world.ts`): потоки выводятся из
  пары «зерно + имя», остальные системы не сдвигаются. Только точная математика в `src/sim` (ADR-009).
- **Светлячки — постоянная часть мира** (ADR-018, решение владельца): не удалять. До шага 1.5 их видно только в
  отладочной сцене `clock`; шаг 1.5 выводит их на карту.
- **Проверка кадров** (с шага 0.8): `npm run shot -- … --compare docs/screenshots/<шаг>` сравнивает новые кадры с
  прежними пиксель в пиксель (контрольные сцены — без единого отличия, если шаг их не касается);
  `--check-crisp N` с `ui=0` доказывает резкость пикселей на ×N. Меняешь меню, сцену `world` или сохранения —
  `npm run e2e` (сквозная проверка в браузере).
- Тексты для игрока до шага 1.6 — строками в коде, как сейчас; с 1.6 — только через модуль текстов.

**GDD:** §2 (архитектура), §4.2 (потребности), §13.1–13.2, §10 (внешний вид), §11.1.

### 1.1 — Карта 64×64 и её отрисовка

**Цель.** На экране — кусочек мира: трава, вода, деревья, кусты.

**Сделать.**

- Карта в `src/sim`: размер, слои тайла по GDD §2.2 (пока — грунт и объект), типизированные массивы,
  чанки 32×32. Заложить место под скрытые поля тайла (плодородие, влажность, износ…), не заполняя их.
- Объекты мира (дерево, куст, камень) как сущности с позицией и состоянием. Виды объектов — **таблица данных**
  (например, `data/objects.json`: id, название, спрайт, проходимость; урожай и возобновление добавят шаги 1.4 и
  1.11) — по правилу «содержание в таблицах» (`docs/ARCHITECTURE.md`, «Как добавить поле или таблицу»).
  Спрайты есть с шага 0.4: `tree`, `tree_young`, `birch`, `stump`, `berry_bush` (с ягодами / пустой), `stone`,
  `branches`, украшения `flowers`, `grass_tuft`.
- Простой генератор по зерну: поляны, лесные массивы, река или озеро с берегом, ягодные кусты, камни.
  Гарантии: есть вода, лес и не меньше заданного числа кустов; есть сухое место под стоянку.
  Случайность генератора — свой поток (`map`) в конце `RNG_STREAMS` (после `fireflies`); карта строится в `createWorld(seed)`
  (её вызывают все тесты и прогоны — генерация должна быть быстрой: замер в отчёт).
- Отрисовка в `src/render`: карта рисуется чанками, закешированными во внекадровые холсты; объекты сортируются
  по вертикали (дерево перекрывает то, что за ним); анимация воды; переходы между типами земли по правилу из `docs/ART.md`.
  Готово с шага 0.4: сборка тайла с переходами (`composeTerrainTile`), слой земли с кешем состояний ряби
  (`createTerrainLayer` — разрезать на чанки), сборка картинки «тени → предметы по глубине» (`createScenery`).
  Реки и озёра генерировать связными по сторонам тайлов (не только по диагонали) — см. `docs/ART.md`, «Земля».
- Сцена `world` (есть с шага 0.7: мир из автосохранения, автосохранение, панель «Мир») вместо вида ядра
  (`createClockView` из `src/app/clockScene.ts`) рисует карту. Сцена по умолчанию — по-прежнему заставка с меню
  («Продолжить / Новый мир / Загрузить из файла»): в мир попадают через него (ADR-016). Сцена `clock` остаётся
  отладочной (время, журнал, светлячки; на карту светлячки выйдут на шаге 1.5). Контрольные сцены «Мир после загрузки» и «Меню с сохранением» в
  `STATUS.md` переснять: в мире теперь карта, а в меню — тот же мир с картой.
- Карта — новое поле мира, то есть новая форма мира: поднять `SAVE_VERSION` и обновить форму в
  `src/sim/save.test.ts` (упавший тест подскажет порядок). Типизированные массивы сохранение уже умеет.
- Камера пока неподвижна: карта целиком по центру окна в целочисленном масштабе. Параметр `zoom=` (целый 1–4,
  `src/app/params.ts`; без него — наибольший, что помещается) уже есть с шага 0.4 — использовать его.

**Готово, когда.**

- Одно зерно даёт одну и ту же карту, разные зёрна — разные (тест).
- Гарантии генератора выполняются на зёрнах 1…100 (тест).
- Мир с картой сохраняется и загружается без изменения истории (тесты сохранений зелёные, размер сохранения — в отчёте).
- Кадр рисуется быстрее 16 мс (замер в отчёте).
- Пиксели резкие: `npm run shot -- --check-crisp 2` (и 4) на кадрах карты с `ui=0`.

**Показать.** Карты трёх разных зёрен целиком.

**GDD:** §2.2, §3.3 (лиственный лес), §10.5 — `docs/gdd/02-simulation-architecture.md`, `docs/gdd/03-world-and-biomes.md`.

### 1.2 — Камера: панорама и зум

**Цель.** Наблюдатель может двигать камеру и приближать.

**Сделать.**

- Камера: положение в мировых координатах, 4 ступени зума ×0,5 / ×1 / ×2 / ×4 (GDD §10.1), зум к точке под курсором,
  плавное движение, ограничение краями карты.
- Управление: перетаскивание мышью, колесо, клавиши WASD/стрелки и +/−; на сенсорном экране — перетаскивание
  пальцем и щипок.
- Отрисовка только видимых чанков и объектов. Готово с шага 1.1: `createMapRenderer(…).draw(ctx, timeMs, view)`
  (`src/render/mapRenderer.ts`) рисует только прямоугольник `view` мира; неподвижный вид — `fitView` в
  `src/app/mapView.ts` (его заменит камера). На окне 1280×720 карта 64×64 на ×1 не помещается — ×0,5 покажет её
  целиком (`BACKLOG.md`, 1.1). Время кадра — `npm run shot -- --frame-time 4000 …`.
- Параметры адресной строки `cam=x,y` и `zoom=`. `zoom=` уже есть (целый 1–4, `ZOOMS` в `src/app/params.ts`,
  шаг 0.4): сделать его ступенью камеры и добавить `0.5`; сцены `stylesheet`/`gallery` продолжают его понимать.
- **Экраны с дробным масштабом** (Windows 125 %, 150 %; `BACKLOG.md`, 0.3): холст — в физических пикселях
  (`devicePixelRatio`), целый масштаб считается от них; иначе пиксели выходят разной ширины.
- Тесты математики камеры: экран ↔ мир, ограничения, зум к точке.

**Готово, когда.**

- Камера двигается и приближается мышью, клавиатурой и пальцами; пиксели остаются резкими на всех ступенях
  (×2 и ×4 — `npm run shot -- --check-crisp 2` / `4` с `ui=0`; ×0,5 — без сглаживания, каждый второй пиксель;
  дробный `devicePixelRatio` — кадр с `--scale 1.25`).
- За края карты камера не выходит; при зуме точка под курсором остаётся под курсором.

**Показать.** Одно и то же место на четырёх ступенях зума.

**GDD:** §1.3, §10.1 — `docs/gdd/01-pillars.md`, `docs/gdd/10-visual-style.md`.

### 1.3 — Житель: ходьба и поиск пути

**Цель.** В мире появляются двое — мужчина и женщина — и умеют ходить, обходя воду.

**Сделать.**

- Сущность «житель»: id, пол, позиция (тайл + продвижение к следующему), направление взгляда, текущее действие.
- Выбор стартовой точки простой оценкой: рядом вода и лес, сухо (упрощённый GDD §3.1, п. 9). Готово с шага 1.1:
  `findCampSite(map, objects)` (`src/sim/mapgen.ts`) — центр сухого свободного квадрата 5×5 у воды и леса; генератор
  гарантирует, что он есть. Проходимость тайла — `isPassable` (`src/sim/objects.ts`): вода и объекты с
  `walkable: false` (деревья, пни, кусты, валуны) мешают, цветы и высокая трава — нет.
- Поиск пути A* по тайлам: вода и деревья непроходимы, без срезания углов; стоимость зависит от типа земли
  (задел под тропы из GDD §6.1); недостижимая цель обрабатывается без зависаний; ограничение на объём поиска.
- Движение: 1 тайл за 4 тика по траве (GDD §13.1); двое не стоят в одном тайле.
- Отрисовка: плавное перемещение между тайлами (интерполяция `loop.alpha`, как у светлячков в `clock`),
  анимация ходьбы по направлению, стойка «дышит». Спрайты `man` / `woman` с ходьбой в 4 стороны и перекраской
  кожи и волос — с шага 0.4. **Кадр ходьбы выбирать по пройденному пути, а не по времени показа**
  (`BACKLOG.md`, 0.4): иначе на ×20 ноги шагают как на ×1.
- Пока нет потребностей — спокойное блуждание возле точки старта.
- Отладка (`debug=1`): щелчок по тайлу отправляет выбранного жителя туда; путь рисуется линией.
  Готово с шага 1.2: камера (`src/app/cameraControl.ts`, `src/render/camera.ts`) — точка экрана в мир:
  `screenToWorld(camera.layout, x, y)` (x, y — физические пиксели холста; тайл — делить на 16). Щелчок пока не
  отличается от перетаскивания: в `createGestures` добавить «касание без движения» (сдвиг меньше нескольких
  пикселей) и не мешать перетаскиванию карты. Жители рисуются в тот же буфер 1:1, что и карта
  (`src/app/mapView.ts`, `render`), — тогда они резкие на всех ступенях и на ×0,5 без мерцания.

**Готово, когда.**

- Житель доходит до указанной точки в обход воды (сценарный тест на карте с рекой).
- Недостижимая цель не вешает игру и не ломает жителя (тест).
- Жители никогда не оказываются в воде или внутри дерева (тест-инвариант на 5 000 тиков).
- Детерминизм сохранён.

**Показать.** Двое на карте крупно; путь в обход воды с отладочной линией.

**GDD:** §2.2, §2.4 (про пути), §10.2, §13.1 — `docs/gdd/02-simulation-architecture.md`, `docs/gdd/10-visual-style.md`.

### 1.4 — Сытость и жажда: ягоды и вода

**Цель.** Жители сами находят еду и воду и не умирают.

**Сделать.**

- Потребности «сытость» и «жажда», шкалы 0–100, скорости падения из GDD §4.2 (в `data/`).
- Ягодный куст хранит число ягод; действие «собрать и съесть»; действие «пить» у кромки воды.
- Выбор действия — сразу как маленький полезностный выбор: полезность = нужда² × доступность
  (GDD §2.3), с лёгкой случайностью. Устройство должно расшириться на шаге 1.8 без переписывания.
- Здоровье. При нуле сытости или жажды здоровье падает; смерть через ~4 и ~2 суток соответственно (GDD §4.2).
  Смерть записывается в журнал событий **с причиной**.
- Отладочные шкалы над головой (`debug=needs`).
- Числа потребностей — новый раздел `data/balance.json` (схема — `src/data/tables.ts`); событие смерти — новый
  тип в `EventBody` (`src/sim/events.ts`), причина-нужда — новый вид в `Cause`. Показатели прогонов: смерти по
  причинам и **«умер при доступной еде и воде»** (признаки «еда/вода были в досягаемости» — в событии смерти;
  GDD §15.2) — он должен быть 0.
- До шага 1.11 кусты не восстанавливаются: в прогонах дольше запаса ягод жители законно умирают от голода,
  объев округу. Это не ошибка ИИ — показатель выше отличает такие смерти (еды в досягаемости нет).
- Готово с шага 1.3 (ADR-021): жители `world.villagers` (`src/sim/villagers.ts`) с действием `idle` / `walk`
  (`VillagerAction` — добавить «собрать и съесть», «пить» и т. п.); поиск пути `findPath` (`src/sim/path.ts`) —
  куст и вода непроходимы, поэтому цель похода — свободный тайл **рядом** с кустом или кромкой воды (`tileSpeed`,
  `isTaken`, `canStandOn`-подобная проверка); недостижимое — `blocked` / `unreachable` / `too_far`. Сейчас без нужд
  житель отдыхает и бродит у дома (`wander`): полезностный выбор встаёт на место этого решения в `decide`.
  Сценарные карты — строками (`tests/scenario.ts`: `worldOn`, `meadow`; `B` — куст, `~` — вода). Параметр
  `debug=` уже понимает слова через запятую (`params.debug`): `debug=needs` — новое слово.

**Готово, когда.**

- Сценарный тест: на зёрнах 1…20 двое живут 7 суток, потребности не падают до нуля.
- Сценарный тест: без кустов житель умирает от голода, и в журнале причина «голод»; без воды — «жажда».
- Житель не умирает при доступной еде и воде (иначе это ошибка ИИ).

**Показать.** Житель ест у куста; житель пьёт у воды; шкалы потребностей.

**GDD:** §2.3, §4.2, §13.2 — `docs/gdd/04-villager.md`, `docs/gdd/13-balance-numbers.md`.

### 1.5 — Сутки, освещение и сон

**Цель.** День сменяется ночью; ночью оба спят, утром встают.

**Сделать.**

- Освещение по фазам суток: розовый рассвет, день, золотой закат, синяя ночь; плавные переходы (GDD §10.5).
  Реализация — цветокоррекция кадра; заложить возможность «дыр» тёплого света для костра (шаг 1.9).
  Готово на заставке с шага 0.4: ночной фильтр и ступенчатый круг света костра (`src/app/titleScene.ts`,
  `firelight`) — вынести в `src/render` и переиспользовать, а не писать второй раз. С шага 1.2 мир рисуется видимой
  частью в буфер 1:1 и кладётся на экран ступенью камеры (`drawPicture`): свет накладывать на буфер (пиксели мира),
  чтобы кольца света были резкими на всех ступенях.
- Небо отладочной сцены `clock` задано цветами в коде, мимо палитры (`BACKLOG.md`, 0.2) — перевести на то же
  правило суточного света.
- **Светлячки на карте** (ADR-018): рой из `src/sim/systems/fireflies.ts` перевести из отвлечённых координат поляны
  (`FIELD`) в координаты карты — над травой и у воды, не над лесом и глубокой водой; ночью рисовать светящимися
  точками (мигают, плавно летают — интерполяция `prevX`/`x`), не гасить ночным фильтром. Новая форма мира —
  `SAVE_VERSION`.
- Потребность «сон» (100 → 0 за 1,5 суток); действие «спать» на земле с коэффициентом ×0,5 (GDD §4.2);
  ночью желание спать выше; нехватка сна — обморок.
  Готово с шага 1.4 (ADR-023): нужды — `NEEDS` в `src/sim/needs.ts` (сон — новая строка; числа — раздел `needs`
  `data/balance.json`), система «жизнь» `src/sim/life.ts` (шкала на нуле — событие `need_ran_out`), разум
  `src/sim/minds.ts` (`ACTIVITIES`: «спать» — новая деятельность, нужда² × …; ночной множитель — по фазе суток),
  действия жителя `VillagerAction` (`eat`/`drink` — образец для `sleep`), прерывание еды более сильной нуждой
  (`morePressing` в `src/sim/villagers.ts`) — образец «проснётся, если припёрло»; полоски `debug=needs` — `drawNeeds`.
- Спрайт спящего (лёжа; мужчина и женщина). Значок сна — пузырёк `bubble_sleep` (шаг 0.4).
- Сценарный тест на 3 суток.

**Готово, когда.**

- Ночью оба спят не менее 80 % ночного времени, днём бодрствуют (тест).
- Рассвет, день, закат и ночь различимы на скриншотах без подписей.
- Сон не приводит к смерти от голода или жажды (проснётся, если припёрло).

**Показать.** Одно место в четыре времени суток; светлячки над лугом ночью.

**GDD:** §2.1, §4.2, §10.5 — `docs/gdd/02-simulation-architecture.md`, `docs/gdd/04-villager.md`.

### 1.6 — Панель наблюдателя: дата, скорость, события

**Цель.** Минимальный интерфейс, чтобы удобно смотреть.

**Сделать.**

- Верхняя панель: год, сезон, день, значок времени суток, население.

### 1.7 — Предметы как физические объекты

**Цель.** Ресурсы существуют в мире: их поднимают, несут, кладут в кучу.

**Сделать.**

- Сущность «предмет»: тип из `resources.json`, количество (стопка), место — на тайле, в куче или в руках.
- Действия: поднять, нести (в руках — одна стопка, GDD §5.1), положить, сложить в кучу (предел стопки на тайл).
- Понятие «стоянка»: точка сбора у места старта.
- Ветки появляются под деревьями; жители собирают их и носят в кучу у стоянки.
- Отрисовка: предметы на земле (значки ресурсов вида `item`, шаг 0.5), куча растёт визуально (спрайт
  `branch_pile` пока один — нужны ступени размера или складывание из значков), житель с ношей (новая поза).
- Тест-инвариант: количество предметов сохраняется при переносе (ничего не дублируется и не исчезает).

**Готово, когда.**

- Ветки складываются в кучу у стоянки (сценарный тест: через N суток в куче не меньше M веток).
- Инвариант сохранения проходит на 10 000 тиков.
- Ноша видна в руках, куча видна на земле.

**Показать.** Житель несёт ветки; куча у стоянки «до» и «после».

**GDD:** §5.1, §11.3 («Цепочки») — `docs/gdd/05-resources-and-economy.md`.

### 1.8 — Полезностный ИИ с планами

**Цель.** Единый «мозг» жителя: оценивает все возможные действия и выполняет короткие планы.

**Сделать.**

- Действия как отдельные описания: условия, функция полезности (нужда × доступность × характер × контекст,
  GDD §2.3), план из 2–5 шагов («дойти → взять → дойти → положить»).
- Обдумывание раз в 5–20 тиков (не каждый тик), со сдвигом между жителями.
- Прерывание с гистерезисом: слегка голодный доделает работу, сильно голодный бросит всё.
  Брошенная ноша остаётся на земле как предмет.
- Небольшая случайность выбора (через генератор симуляции), чтобы не было роботов.
- Журнал решений жителя: последние N решений с оценками вариантов; показ в отладке.
- Перевести на этот механизм всё поведение шагов 1.3–1.7.
  Готово с шага 1.4 (ADR-023): `src/sim/minds.ts` — `choose` (отдых против `ACTIVITIES` по нужда² × доступность,
  случайность из потока `minds`, ветви и границы `reachFor`, память «нигде нет», предусмотрительность `precaution`),
  след решения `Considered` (задел под журнал решений); обдумывание отдыхающего — раз в `ai.thinkTicks` со сдвигом по
  id; прерывание еды жаждой (`morePressing`) — частный случай гистерезиса.
  С шага 1.7 (ADR-027): работа «отнести в кучу» — вариант `haul` в `choose` (своя выборка случайности после прежних,
  память `villager.noWork`); её план зашит в действия `src/sim/villagers.ts`: `walk/fetch` → `pick_up` → (ещё `fetch`,
  пока руки не полны) → `walk/carry` → `put_down`. Брошенная ноша уже ложится на землю: всё, что не работа, отпускает
  ношу (`hauling`, `dropLoad`); правила предметов в сценариях — `brokenRules` из `tests/items.test.ts`.

**Готово, когда.**

- Сценарный тест: житель с ношей и сытостью 60 донесёт ношу; с сытостью 15 — бросит и пойдёт есть.
- Нет «дёрганья»: в стандартном сценарии житель меняет план не чаще разумного предела (тест).
- По журналу решений можно объяснить любой поступок.
- Все прежние сценарные тесты зелёные.

**Показать.** Отладочный вид решений жителя; общий вид.

**GDD:** §2.3 — `docs/gdd/02-simulation-architecture.md`.

### 1.9 — Костёр

### 1.10 — Тепло, сезоны, погода

**Цель.** Год идёт по кругу; зимой холодно, и без костра не выжить.

**Сделать.**

- Сезоны (3 суток каждый): температура = сезон + время суток + погода.
- Потребность «тепло»: падает на холоде, растёт у огня; при нуле — обморожение, затем смерть с причиной «холод».
- Погода: ясно, облачно, дождь, снег — простая модель переходов по сезону (GDD §3.2). Дождь гасит костёр без укрытия
  медленнее/быстрее — на усмотрение, но правило записать.
- Сезонный вид мира через подмену палитры: весна, лето, осень, зима со снегом. Частицы дождя и снега.
- Еда по сезонам: зимой ягод нет (GDD §3.2). Добавить подножный корм — коренья и орехи (ресурсы эпохи 0)
  с зимней отдачей по GDD §13.2 и хранением (коренья — 1 сезон), чтобы зиму можно было пережить.
  Важно (отзыв владельца после 1.4, ADR-024): сытость тянется 25 суток, жажда — 15, взрослый съедает ≈ 0,1 рациона в
  сутки, а не 1, как в §13.2. Отдачу корма в рационах пересчитать под это (иначе еды будет вдесятеро больше нужного).
- Анимация «дрожит от холода».
- Показатель «пара пережила год» для прогонов (`gauge` — живых на конец года) и **конец мира**: прогон
  останавливает мир, в котором не осталось живых, со статусом `extinct` в `worlds.csv` (`BACKLOG.md`, 0.6;
  `runWorld` в `tools/sim/run.ts`).

**Готово, когда.**

- Сценарный тест: без костра зимой оба умирают, причина «холод» записана.
- С костром и запасом пара переживает год не менее чем на 70 % из 20 зёрен (прогоны; точная настройка — шаг 1.13).
- Сезон узнаётся по одному кадру.

**Показать.** Одно место в четыре сезона; дождь; снег.

**GDD:** §3.2, §4.2, §13.2 — `docs/gdd/03-world-and-biomes.md`, `docs/gdd/04-villager.md`.

### 1.11 — Истощение и возобновление природы

**Цель.** Округа не бесконечна: ближние кусты пустеют, приходится ходить дальше.

**Сделать.**

- Кусты плодоносят раз в год и постепенно; обобранный куст пуст до следующего урожая (GDD §3.2).
- Ветки и подножный корм возобновляются со скоростями из `data/`.
- Житель помнит известные ему источники еды и выбирает ближайший непустой; при нехватке — разведывает дальше.
  Готово с шага 1.4: запас на объекте `stock` (рационы) и `takeFood` (`src/sim/objects.ts`), поле `harvest` в
  `data/objects.json` (малина — 4 рациона, пустая — `empty`); поиск ближайшего источника — `findNearest`
  (`src/sim/path.ts`) через `searchSource` (`src/sim/minds.ts`); память пока одна — «нигде нет» (`villager.nowhere`).
  В голодную пору жители мечутся между далёкими ягодами и водой (`BACKLOG.md`, 1.4) — память и заготовка впрок это
  исправят; со шага 1.11 `npm run bench` снова мерит живой мир.
- Заготовка впрок: излишек ягод несут на стоянку (портятся за 3 суток, GDD §13.2).
  Важно (ADR-024): трапеза теперь раз в ≈ 10 суток — ягоды, портящиеся за 3 суток, запасать бессмысленно; решить с
  владельцем или в `DECISIONS.md`: запасать то, что хранится (орехи, коренья), или удлинить срок порчи.

**Готово, когда.**

- Через сезон жители ходят за ягодами заметно дальше, чем в первые дни (показатель в прогоне, тест).
- Кусты восстанавливаются к следующему году (тест).
- Выживаемость из шага 1.10 не упала ниже порога.

**Показать.** Обобранные кусты у стоянки и полные вдалеке; жители в дальнем походе.

### 1.13 — Ревизия этапа 1

  (живой сборки нет — ADR-011; способ показа согласовать с владельцем, по умолчанию — серия скриншотов
  с подписями); отзыв записать в `docs/FEEDBACK.md`.
- Уточнить карточки этапа 2.

**Готово, когда.**

- Критерии шагов 1.1–1.12 перепроверены; показатели прогонов — в `STATUS.md`.
- Нелепых смертей в 50 прогонах нет.
- Карточки этапа 2 уточнены.

**Показать.** Три кадра «жизни двоих»: утро, вечер у костра, зима.
